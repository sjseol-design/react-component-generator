# commit: 변경사항 분석 후 컨벤션 커밋

변경사항을 읽고 논리적 단위로 나눠 한국어 커밋 메시지로 커밋한다. 별도의 사용자 승인 절차 없이 바로 커밋한다.

## 워크플로우

### Step 1: 변경사항 분석

다음을 실행해 현재 상태를 파악한다.

```bash
git status --short
git diff            # unstaged
git diff --staged   # staged
git log --oneline -10   # 기존 메시지 스타일 확인
```

- git 저장소가 아니거나 변경사항이 없으면 그 사실만 알리고 종료한다.
- untracked 파일은 `git status`로 목록을 확인하고, 필요하면 내용을 읽어 성격을 파악한다.
- `.env`, 키·토큰·자격증명 파일, `node_modules`, `dist` 등 커밋하면 안 되는 파일이 보이면 제외하고 사용자에게 알린다.
- 이미 staged된 항목이 있으면 사용자가 의도한 것으로 보고 존중한다. 임의로 unstage하지 않는다.

### Step 2: 논리적 단위로 분류

변경 파일과 hunk를 목적별로 묶는다. 하나의 커밋은 하나의 목적만 가진다.

- 기능 추가와 그 기능의 테스트는 같은 커밋에 둔다.
- 버그 수정, 리팩터링, 설정·의존성 변경이 섞여 있으면 따로 나눈다.
- 한 파일에 서로 다른 목적의 변경이 섞여 있으면 `git add -p` 대신 파일 단위로 묶을 수 있는지 먼저 본다. 쪼개야 한다면 사용자에게 알린다. (`-i` 대화형 플래그는 이 환경에서 쓸 수 없다.)
- 변경이 작고 단일 목적이면 커밋 1개로 충분하다. 억지로 나누지 않는다.

### Step 3: 한국어 커밋 메시지 작성

형식:

```
<type>: <요약>

<본문 (선택)>
```

type:

| type | 용도 |
| --- | --- |
| `feat` | 사용자에게 보이는 새 기능·디자인 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 구조 개선 |
| `chore` | 설정, 의존성, 빌드, 문서 등 기타 |

작성 규칙:

- 요약은 한국어, 50자 안팎, 마침표 없이 쓴다. "무엇을 했는가"를 명령형·명사형으로 쓴다. (예: `feat: 레트로 워크벤치 테마 적용`)
- `git log`에서 확인한 기존 저장소 스타일이 있으면 그것과 어긋나지 않게 맞춘다.
- 본문은 "왜" 바꿨는지가 diff만으로 드러나지 않을 때만 쓴다. 변경 목록을 나열하지 않는다.
- 세션 환경이 커밋 메시지 끝에 붙일 attribution(Co-Authored-By 등)을 지정했다면 그대로 마지막에 추가한다. 지정이 없으면 임의로 붙이지 않는다.

### Step 4: 커밋 계획 안내

커밋하기 전에 아래 계획을 출력한다. 승인을 기다리지 않고 곧바로 Step 5로 진행한다.

```
커밋 계획 (N개)

1. feat: 레트로 워크벤치 테마 적용
   - src/App.css
   - src/index.css
2. chore: galmuri 폰트 의존성 추가
   - package.json
   - bun.lock

제외한 파일: .env (민감 정보)
```

- 사용자가 커밋 전에 메시지나 분류를 직접 지정했다면 그 내용을 계획에 반영한다.

### Step 5: 커밋 실행

계획대로 단위마다 순서대로 실행한다.

```bash
git add <해당 단위의 파일들>
git commit -m "<메시지>"
```

- 파일은 이름을 지정해 add 한다. `git add -A`/`git add .`는 제외 대상까지 포함할 수 있으므로 쓰지 않는다.
- 여러 줄 메시지는 heredoc으로 전달한다.
- pre-commit 훅이 실패하면 `--no-verify`로 우회하지 않는다. 원인을 파악해 고치고 **새 커밋**으로 다시 시도한다. `--amend`는 사용자가 요청할 때만 쓴다.
- 현재 브랜치가 기본 브랜치(main/master)면 변경 내용에 맞는 이름으로 새 브랜치를 만들어 그 위에 커밋하고, 결과 보고에 브랜치명을 알린다.

### Step 6: 결과 보고

`git log --oneline -N`으로 만들어진 커밋을 보여주고, 커밋하지 않은 남은 변경이 있으면 함께 알린다. push는 하지 않으며, 원하면 사용자가 따로 요청하도록 안내한다.

## 하지 않는 것

- 임의의 push, force 옵션
- git config 변경
- 훅·서명 우회 (`--no-verify`, `--no-gpg-sign`)
- 비밀 정보가 담긴 파일 커밋
